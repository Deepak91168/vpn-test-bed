# Issues and limits

Updated 2026-10-03. Configuration instructions and commands are in [README.md](README.md).

1. **Individual websites can still fail.** The original ranks 1–100 list contained many non-homepage hosts; the revised `sites.txt` selected 100 tested HTTPS homepages, and the Pi's 24-session mixed run succeeded on 72/72 visits. A later 25-session UDP run had one `webex.com` HTTP 403 response among 75 visits, so one session was correctly marked failed while its VPN capture was preserved. Treat the URL list as a workload snapshot, not a guarantee that every site will always respond.
2. **This network still depends on the desktop web proxy.** Direct desktop public HTTPS times out. The configured proxy reached the 100 revised sites in two checks; availability can change. `WEB_PROXY=` empty in the selected `hosts/*.env` requests direct desktop egress and does not fall back to the proxy.
3. **Web traffic is curl page fetching.** It downloads HTTP(S) responses and follows redirects inside the VPN namespace. It does not render JavaScript or interact with a browser. The PCAP proves encrypted VPN traffic; use per-visit metadata to establish which HTTPS requests succeeded.
4. **Historical web-success totals need care.** Before proxy-login detection was added, some HTTP 200 login pages were counted as web successes. Do not use those counts in `openvpn-validation-mixed-20261002T183759-6605` or `openvpn-reneg-mixed-validation-20261002T223019-7c30` as evidence of visits to selected domains. Their VPN/PCAP/rekey data remains useful. Current results record the requested/final URL and reject detected proxy login responses.
5. **Mixed rekey targets are timing goals, not exact counts.** The default all-eight mixed scheduler balances targets of 0, 1, and 2 renewals and records both target and observed count. OpenVPN renews by elapsed time; a slow web request can extend a session and cause extra renewals. In the verified Pi nine-session total-N run, UDP vanilla targeted two renewals but observed one. Use observed `renegotiation_events` for analysis. Explicit `--reneg-sec R` retains the shared-R behavior used in the earlier Pi final check.

**Validated on Pi:** all eight UDP/TCP × control-protection modes, 24/24 Wikipedia HTTPS fetches in the earlier mixed run, 24/24 revised-list visits in the final mixed run, 24/24 visits in the automatic mixed rekey run, strict filtered PCAPs, verified desktop transfer, and Ctrl+C partial-result cleanup. The explicit-R final run observed four renewals per session; the automatic run observed 0–2. The new total-N path was validated live with nine sessions over eight modes; all nine Wikipedia HTTPS visits succeeded and the desktop copy's checksums verified. After the prior interruption the user confirmed an empty namespace list and normal `wlan0` route. The old setup and GitHub were not changed.
